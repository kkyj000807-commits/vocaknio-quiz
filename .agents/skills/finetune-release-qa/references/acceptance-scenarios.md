# 독립 인수 시나리오

각 평가는 구현자의 결론을 전달받지 않고 현재 코드·데이터·공개 결과만으로 수행한다. 해당 작업과 무관한 시나리오는 실행하지 않는다.

## 100단어 보강 요청

- 요청된 100개 전부가 manifest에서 `production / withheld / unmapped` 중 하나로 귀결되는지 센다. 이는 이 인수 시나리오의 입력 조건이지 모든 batch를 100개로 제한하는 규칙이 아니다.
- production 항목은 stable item/sense ID, 품사·구문, 뜻·초월번역·예문, provenance·권리를 만족하고 index/loader/UI 수가 일치해야 한다.
- 다의어, 반복 행, 숙어, 긴 텍스트를 포함한 사전 선언 표본을 확인한다. 보류 항목을 완료 수에 넣지 않는다.

## 다의어 정답

- 같은 표제어의 서로 다른 두 sense를 새 문맥에서 각각 출제한다.
- 문맥상 정답은 하나이고 오답은 해당 sense와 겹치지 않아야 한다. 정답 뒤 해설의 sense ID·뜻이 문제와 일치해야 한다.
- 뒤로가기·재개 뒤에도 같은 sense와 선지·채점이 유지되며 표제어 fallback으로 바뀌지 않아야 한다.

## 저장 복원

- 정답, 오답, 패스, 입력 초안/힌트를 포함해 이동·새로고침·재시작을 검사한다.
- 중복 통계·오답 부활·북마크 유실이 없고 완료/조건 변경 세션은 재사용되지 않아야 한다.
- 깨진 기존 기록은 삭제되지 않고 경고·백업·복구 경계가 보여야 한다.

## 모바일 하단과 학습 이동

- 좁은 화면에서 `문풀·단어장·오답·통계·설정`이 안전 영역에 가리지 않고 터치 가능해야 한다.
- 세로 스크롤, 가로 이동, 이전/다음, 키보드·긴 해설을 확인한다. 실제 기기가 없으면 브라우저별 실기기 결과는 `NOT_VERIFIED`다.

## 릴리스

- 생성기와 검증을 통과한 소유 후보만 source 커밋하고 그 SHA에서 새 빈 Production 빌드와 산출물 감사를 실행한다. manifest의 소스·데이터·시각이 이 후보 SHA와 일치해야 한다.
- 빌드 전후 소스·데이터·생성기 입력이 바뀌면 이전 후보 증거를 폐기하고 새 SHA에서 검증·커밋·빌드·감사를 다시 한다. 사용자 dirty 파일을 포함하거나 정리하지 않는다.
- 원격 SHA, Pages 성공, 공개 URL의 release 정보·변경 동작·자산 응답을 확인한다.
- 일반 재접속에서 이전 캐시가 남지 않아야 한다. Preview나 로컬 결과를 Production 증거로 사용하지 않는다.

# VOCA NEXUS 현재 작업 상태

이 문서는 대화 원문을 쌓는 기록이 아니라, 다음 작업에서 즉시 이어가기 위한 최신 사실만 유지한다.

## 단일 작업실 규칙

- Codex 주 작업실은 고정된 `VOCA NEXUS 통합 작업실` 하나다.
- VOCA 작업을 위해 새 대화, 보조 작업, 비중복 분석 작업을 만들지 않는다.
- 조사, 구현, 검증, 배포, 브리핑을 모두 같은 작업실에서 이어간다.
- 컨텍스트가 축약되면 이 문서, `docs/AI_WORK_RULES.md`, `git status`를 먼저 읽고 계속한다.
- 과거 대화 전체를 다시 탐색하지 않고 이 문서의 현재 사실을 기준으로 삼는다.
- 별도 작업이 꼭 필요하면 먼저 사용자에게 이유와 범위를 설명하고 승인을 받는다.

## 사용자 목표

- 알바 휴식이나 식사 중 5~10분 사용하는 편입영어 보조 학습 앱이다.
- 기능 수보다 정답 판정, 뜻, 동의어의 정확성이 우선이다.
- 기본 학습은 10문제로 빠르게 시작할 수 있어야 한다.
- 크롬과 사파리에서 같은 기본 화면과 안정적인 학습 흐름을 제공해야 한다.
- 코드 수정만이 아니라 실제 공개 사이트에 반영되고 동작해야 완료다.

## 현재 구현

- VOCA NEXUS v1.4 정본: 38,163개 단어.
- 일반 퀴즈와 오답 복습은 공통 v1.4 퀴즈 엔진을 사용한다.
- 홈의 v1.4 범위에서 실제 퀴즈로 진입할 수 있다.
- GitHub Pages 기본 경로는 `/vocaknio-quiz/`다.
- 밝은 테마 기본 배경은 미색 `#F5F0E6`, 표면은 `#FFFCF5`, 카드는 `#EEE5D6`이다.
- 새 브라우저의 기본값은 밝은 테마다.
- 테마는 기기 시스템 설정을 따르지 않고 앱의 밝게/어둡게 선택만 따른다.
- HTML `color-scheme`, 시작 배경과 스플래시도 앱 테마 기준으로 고정한다.
- 저장소 접근이 실패해도 테마 로딩이 빈 화면으로 멈추지 않는다.
- 퀴즈에는 44px 이상의 명시적 뒤로가기 버튼과 스와이프 안내가 있다.
- 연속 터치로 문제가 두 칸 넘어가지 않게 전환을 잠근다.
- 모바일 웹의 일반·기출 퀴즈는 전체 화면 가로 제스처 감지기를 사용하지 않고 브라우저 기본 세로 스크롤을 단독 사용한다.
- 웹 스크롤 영역은 `touch-action: auto`, `user-select: auto`이며 문제 이동은 `다음 →` 버튼을 사용한다.
- 네이티브 앱에서는 정답 후 왼쪽 가로 넘김을 유지한다.
- 다음 문제 상태는 애니메이션 완료 콜백과 분리되어 Safari에서 애니메이션 콜백이 누락돼도 진행된다.
- 단어장·오답·결과·하단 탭의 주요 터치 영역은 44px 이상이다.
- 눈·원숭이 이모지는 중립적인 잠금 아이콘으로 교체했다.
- 단어장 범위는 최종 정본 기준으로 `전체 → V101 → V201 → V301 → V401 → V501 → V502 → V601 → 부록 → 숙어·표현` 순서다.

## 현재 배포

- 소스 브랜치: `main`.
- 앱 버전 단일 원본은 `release.config.json`이며 현재 Production 버전은 `1.9.0`이다.
- 설정 화면은 `버전 1.9.0 · 최근 수정 2026.08.14 01:13 KST · Production 기준`을 표시한다.
- Production 소스 커밋: `13e49fb`.
- 공개 브랜치: `gh-pages`.
- 원격 `gh-pages`: `2754ec7`.
- 공개 주소: `https://kkyj000807-commits.github.io/vocaknio-quiz/`.
- 최신 공개 번들: `entry-5979824621aac45195006daec1f68979.js`.
- 직전 번들도 남겨 HTML 캐시가 이전 번들을 요청해도 흰 화면이 되지 않게 했다.
- `release.json`과 모든 HTML의 자동 갱신 장치가 오래 열린 Safari·Chrome 탭의 새 버전을 확인한다.
- 일반 화면은 새 배포 감지 시 한 번 자동 갱신하며, 진행 중인 퀴즈 화면은 진도 보호를 위해 갱신을 보류한다.
- 390×844 Chromium 공개 사이트에서 정답 전 스크롤 `0 → 35px`, 피드백 후 `35 → 272px` 이동을 확인했다.
- 같은 공개 흐름에서 선택지 → 피드백 → `다음 →` → `2 / 10` 진행을 확인했다.
- 쿼리 없는 기본 공개 URL과 설정 화면에서 버전 1.9.0 및 기준시점을 확인했다.
- 이 Windows 환경에는 연결된 외부 Chrome 제어가 없어 실제 Chrome 확장 세션 확인은 하지 못했다.
- 실제 iOS Safari 화면 확인은 한 번 더 필요하다.

## 작업 트리 주의사항

- 여러 기존 미커밋 파일과 분석 산출물이 남아 있다.
- 사용자가 만든 변경을 reset, 삭제, 일괄 커밋하지 않는다.
- 작업 목적과 직접 관련된 파일만 명시적으로 골라 커밋한다.
- `analysis/`, `build/`, `output/`, `qa_claude/`, `tmp/`, `vocab_project/`는 현재 자동 정리하지 않는다.

## 다음 우선순위

1. 모바일 Safari 실제 공개 URL에서 미색·버전·기준시점·터치 동작을 확인한다.
2. 수정 전 기존 흐름과 저장 데이터 호환성을 확인한다.
3. 관련 전용 검사와 실제 사용자 흐름을 검증한다.
4. 브리핑에는 시간, 변경, 배포, 막힘, 다음 한 가지만 간결하게 남긴다.

# AI 작업 규칙

## 1. 현재 지시와 범위

- 새 지시는 기존 요구와 비교해 유지·강화·교체·추가·보류·제외로 통합한다. 최신의 구체적인 지시가 우선한다.
- 데이터·ID·학습 기록·정답·권리·사용자 변경 보호와 검증 없는 완료 금지는 계속 유지한다.
- 증상 → 실제 코드·데이터 경로 → 재현 → 원인 → 필요한 수정 순으로 판단한다. 근거 없는 리팩터링과 패키지 변경은 하지 않는다.
- P0(정답·기록·데이터·사용 차단) → P1(매일 학습·문제 품질·모바일) → P2(적응형·sense·기출 환류) → P3(구조·자동화) 순으로 처리한다.

## 2. 진입과 협업

- `AGENTS.md`의 최소 진입 경로를 따른다. 관련 없는 문서와 과거 대화를 매번 전부 읽지 않는다.
- 수정 전 Git 상태와 소유 파일을 확인하고 `docs/AUTOMATION_RUNBOOK.md`의 OS 잠금을 사용한다.
- 병렬 작업은 파일 소유권을 먼저 나눈다. 같은 파일의 동시 편집, 생성기·전체 검사·빌드·배포의 병렬 실행을 금지한다.
- 보조 에이전트는 배정받은 파일만 수정하고, 공유 파일 변경이 필요하면 코디네이터에게 반환한다.
- 기존 미커밋 변경을 삭제·reset·덮어쓰기·광범위 stage하지 않는다.

## 3. 작업 단위와 검증 사다리

- 콘텐츠 작업은 의미 있는 대량 batch로 진행할 수 있다. 고정된 단어 수·분량·시간이 아니라 입력 품질, 위험도, 검증 가능성, 자원 한계로 batch 경계를 정한다.
- 엔진의 재현된 P0는 진행 중 콘텐츠나 UI보다 먼저 닫는다. 대량 콘텐츠 작업과 엔진 변경은 파일 소유권과 검증 결과를 분리한다.
- **영향 검사**: 변경한 계약과 가장 가까운 감사·테스트·lint를 먼저 실행한다.
- **통합 회귀**: batch가 공유 데이터, 정답, 저장, 라우팅 또는 생성물을 바꾸면 관련 흐름과 `node scripts/verify-project.mjs`를 직렬 실행한다.
- **검증 릴리스**: 승인된 누적 변경만 깨끗한 새 출력에 빌드하고 Production 감사·배포·공개 확인을 수행한다.
- 작은 문구·후보 자료 수정마다 전체 빌드와 배포를 반복하지 않는다. 그러나 통합 계약을 바꾼 batch를 릴리스할 때 전수 게이트를 생략하지 않는다.
- 기존 테스트와 helper를 먼저 확장하고 같은 목적의 복제본을 만들지 않는다. 기존 경계로 표현할 수 없는 계약에는 테스트 가능한 최소 helper를 추가할 수 있다. 테스트 삭제·완화로 실패를 숨기지 않는다.

## 4. 콘텐츠·근거·권리

- 문제 단위는 `word + sense + concept`다. 표제어 문자열이나 한국어 일부 일치만으로 정답을 확정하지 않는다.
- 후보 → sense 분리 → 근거 대조 → 의미핵·초월번역·대조·예문 → 문항 계약 → reviewed/production 승격을 구분한다. 후보를 자동 승격하지 않는다.
- 재현된 P0를 먼저 닫고, 전체 범위의 합법적 기본 사전 coverage를 확보한 뒤 고위험 숙어·다의어·동의어 밀집군·기출 오답 연결을 집중 검수한다. 특정 항목의 깊이 검수가 전체 기본 coverage를 막지 않으며, 수록 행·고유 표현·검수 sense·문항 수를 따로 센다.
- 모든 항목을 같은 방식으로 사전 두 곳에서 수동 전수 조회하지 않는다. 재배포 가능한 정본과 기존 provenance를 batch로 검증하고, 다의어·충돌·부분 동의·강도·격식·polarity·고위험 문항만 독립 근거를 추가 확인한다.
- 기존 스키마가 복수 출처를 요구하면 실제 독립 근거로 충족하거나 별도 계약 마이그레이션을 한다. 같은 원전의 재인용을 둘로 세거나 가짜 출처를 만들지 않는다.
- 무료 열람과 재배포 허가는 구분한다. 접근할 수 없는 원문은 미확인으로 남기며 제한을 우회하지 않는다.
- 재배포·표시 권리가 확인되고 provenance와 검수 상태가 명시된 기본 사전 참고는 별도 참고층에 표시할 수 있다. 미검수 참고를 production 정답 근거나 사전의 공식 번역으로 오인시키지 않는다.
- 영영 정의 원문·실제 음성은 라이선스와 attribution이 확인된 자료만 내장한다. 한국어 해설·창작 예문을 사전의 공식 번역으로 표시하지 않는다.
- 뜻·숙어·초월번역·문항 작업에는 `transfer-english-reasoning`과, 대량 처리면 `finetune-content-pipeline`을 적용한다.

## 5. 정답·출제·학습 기록

- 같은 품사·sense·문맥에서 정답 하나와 겹치지 않는 오답을 보장한다. 근거가 부족하면 안전하게 비출제한다.
- 기본 방향은 영→한 sense, 영→영 synonym/paraphrase, 문맥 sense, contrast다. 플래시카드와 직접 입력은 보조 학습으로 보존한다.
- 한 세션은 범위 순환을 중심으로 하고 약점 복습은 제한한다. 현재 계약의 coverage·review 비율을 바꾸면 근거와 회귀 검사를 함께 남긴다.
- 정답·오답·패스·헷갈린 선택을 다음 출제에 반영하되, 본 문풀·보조 연습·계정 동기화 여부를 섞어 보고하지 않는다.
- 저장은 기존 공통 큐·journal·migration을 통한다. 안정 ID와 기존 키를 임의 재사용·초기화하지 않는다.
- 깨진 기록과 옛 세션은 원본을 보존한다. 승인 데이터가 바뀐 세션을 자동 재채점하지 않는다.
- 복원은 문제·선지·응답·위치·입력 초안·힌트·채점 상태를 일관되게 다룬다. 여러 탭 원자성을 검증하지 않았다면 보장했다고 쓰지 않는다.
- 엔진·저장·복원 변경에는 `finetune-learning-engine`을 적용한다.

## 6. 사용자 흐름과 모바일

- 기본 흐름은 `문풀 → 범위/문제 수 → 풀이 → 이전/다음 → 결과 → 오답 복습 → 새로고침`이다.
- 기본 하단 메뉴는 `문풀 → 단어장 → 오답 → 통계 → 설정`이다. 숨긴 화면과 데이터는 별도 승인 없이 삭제하지 않는다.
- 정답 전 해설 노출, 뜻 가림 중 접근성 노출, 세로 스크롤을 침범하는 가로 제스처를 막는다. 버튼 이동과 충분한 터치 영역을 유지한다.
- 빈 데이터·긴 텍스트·오류·저장 실패에도 안내와 돌아갈 길을 제공한다.
- 데스크톱 에뮬레이션을 실제 모바일 Safari·Chrome 검증으로 보고하지 않는다.

## 7. 릴리스와 완료 판정

- 배포는 현재 승인 범위와 `finetune-release-qa`에 따라 누적된 검증 batch를 대상으로 한다. 생성기 → 영향·통합 검증 → 소유 후보만 source 커밋 → 그 SHA의 새 빌드·감사 → 승인된 Pages 반영 → 공개 확인 순서를 지킨다. 입력이 바뀌면 검증·커밋·빌드·감사를 새 SHA에서 다시 한다.
- Production 전 인증·대상 저장소/브랜치·base path·새 출력·환경을 확인한다. force push와 검증 우회는 금지한다.
- 사용자 dirty 파일을 릴리스에 섞거나, 정리·reset·stash하여 깨끗한 상태를 만들지 않는다.
- 표시 버전과 데이터 버전은 현행 설정·빌드 메타데이터에서 읽는다. 문서나 스킬에 변동 숫자·시각을 복제하지 않는다.
- 빌드, push, 배포 명령 성공만으로 완료라 하지 않는다. 원격 SHA와 실제 공개 URL의 release 정보·변경 동작·자산·캐시를 확인한다.
- 실제 기기를 확인하지 못한 Safari·Chrome 결과는 `NOT_VERIFIED`로 보고한다. Preview를 Production으로 부르지 않는다.

## 8. 보고와 상태 문서

- 보고는 `시간 / 바뀐 점 / 배포 상태 / 막힌 점 / 다음 일`을 기본으로 하고, 검증은 `영향 검사 / 통합 회귀 / 웹 빌드 / 공개 사이트`로 나눈다.
- 코드 작성, 로컬 검증, 배포 준비, Production 확인을 구분한다. 일부 coverage를 전 범위 완료로 확대하지 않는다.
- WORKING_CONTEXT에는 현재 사실·결정·검증·남은 P0·다음 조건만 유지한다. 대화 원문·비밀·인증값을 저장하지 않는다.
- 중앙 DB 관련 작업은 `docs/MASTER_DB_SYNC_RULES.md`를 적용한다. 실제 연결하지 못한 자료는 `sync_required`로 남긴다.

과거의 고정 소규모 작업·항목별 전수 조회·매 수정 전체 배포 규칙은 실행 규칙이 아니다. 원문은 `docs/history/superseded-work-rules.md`에 추적용으로 보존한다.

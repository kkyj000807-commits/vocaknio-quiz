# 정기 감사·개발·릴리스 운영

## 정본과 권한

- 활성 예약, 목적, 대상 대화, 배포 권한의 정본은 `C:/Users/USER/.codex/automation-audits/finetune/POLICY.md`와 `REGISTRY.md`다. 이 문서에 시간표나 변동 버전을 복제하지 않는다.
- 현재 확인 스냅샷에서 A는 `FINETUNE A · 2시간 안정화·배포`, `ACTIVE`, 2시간 간격이다. 이후 값이 다르면 외부 POLICY/REGISTRY와 목적 도구의 실제 상태가 우선한다.
- 기존 FINETUNE 통합 worktree에서 사용자 변경을 보존해 이어간다. 원본 main을 자동 반영·reset하거나 force push하지 않는다.
- 자동화 설정은 목적 도구로만 바꾸며 설정 파일을 직접 편집하지 않는다. 새 예약·대화·worktree를 반복 생성하지 않는다.
- 배포는 외부 정책에 배포 권한이 있는 실행만 수행한다. 감사 전용 실행은 배포하지 않는다.

## 실행 진입

1. 외부 POLICY/REGISTRY, `AGENTS.md`, `docs/WORKING_CONTEXT.md`, 현재 작업에 해당하는 전문 스킬, Git status/diff를 읽는다.
2. 기능 위치나 명령이 필요할 때만 `docs/DEVELOPMENT.md`의 관련 절을 읽는다. 모든 프로젝트 문서를 매회 전부 읽지 않는다.
3. 관련 변경·새 근거·환경 회복이 없으면 `NO_CHANGE`로 끝낸다. 같은 소스 커밋과 입력에 대한 통과 결과는 유효 범위에서 재사용한다.

## OS 잠금과 파일 소유권

- 수정 전 Git common-dir OS 잠금을 획득한다. Windows 한글 경로에서는 해당 프로세스에 `PYTHONUTF8=1`을 설정하고 `python scripts/hold-development-lock.py`를 대화형으로 실행한다.
- `LOCK_BUSY`면 수정하지 않는다. `LOCK_ACQUIRED`의 세션/PID를 기록하고 종료 시 같은 터미널에 Enter를 보내 `LOCK_RELEASED`를 확인한다.
- 소유 프로세스가 살아 있는 잠금을 종료하지 않는다. 중단된 정확한 잠금 PID만 확인 후 정리하며 불확실하면 작업을 건너뛴다.
- 한 코디네이터가 잠금을 소유한 병렬 실행에서는 하위 작업이 재잠금하지 않는다. 파일 소유권을 먼저 나누고 공유 생성기·검사·빌드·배포는 코디네이터가 직렬 실행한다.

## 작업과 검증

- P0 정답·기록·데이터·사용 차단을 먼저 해결하고, 전체 기본 coverage를 확보한 뒤 고위험 숙어·다의어를 집중 검수한다. 이 단계들은 콘텐츠 대량 batch, 엔진, UI의 독립 소유 파일로 병렬화할 수 있다.
- batch 크기는 고정 시간이나 수정 개수가 아니라 입력 품질·영향 범위·검증 가능성·자원 상태로 정한다.
- 작성 중에는 관련 감사·테스트·lint만 실행하고, 공유 계약이 모이면 영향 검사를 통과한 뒤 통합 회귀를 직렬 실행한다.
- 콘텐츠/엔진/UI가 합쳐진 릴리스 후보에서만 전체 검증과 새 Production 빌드를 실행한다. 기존 테스트/helper를 우선 확장하고, 필요한 최소 helper 외의 복제나 실패 조건 완화를 하지 않는다.

## 승인된 릴리스

1. GitHub 인증, 대상 원격/브랜치, 공개 URL, base path를 확인한다.
2. 공유 생성기를 직렬 실행한 뒤 영향 검사와 통합 회귀를 통과시킨다.
3. 파일 소유권 안의 승인 후보만 source 커밋하고 후보 SHA를 기록한다. 사용자 dirty 파일은 포함·정리·reset·stash하지 않는다.
4. 그 source SHA에서 새 빈 출력으로 빌드하고 산출물과 manifest를 감사한다. 과거 출력과 섞지 않는다.
5. 이후 소스·데이터·생성기 입력이 바뀌면 앞선 검증과 후보 SHA를 무효화하고 2번부터 다시 검증·커밋·빌드·감사한다.
6. 승인된 후보만 source 원격과 Pages에 반영한 뒤 Pages 상태와 원격 SHA를 확인한다.
7. 실제 공개 URL에서 release 정보와 식별 가능한 변경, 캐시된 이전 번들, 주요 자산, 문제 시작·저장 복원·모바일 하단 접근을 확인한다.
8. 실제 모바일 Safari·Chrome이 없으면 대신 확인했다고 쓰지 않고 `NOT_VERIFIED`로 남긴다.

P0, 검사 실패, 인증, 네트워크, 사용량 또는 기기 부재가 있으면 가능한 작업과 증거를 먼저 저장하고 차단 지점에서 멈춘다. 조건이 바뀐 뒤 재시도하며 무한 반복하지 않는다.

## 종료 기록

- WORKING_CONTEXT와 외부 최신 보고서에 수정 파일, 영향 검사, 통합 회귀, 빌드/배포, 남은 P0, 다음 재개 조건을 저장한다.
- 앱·PC 종료, 절전, 네트워크, 사용량 제한 뒤 자동 복구는 실제 관찰 전까지 보장하지 않는다.
- 과거 매시간·고정 소규모 운영 원문은 `docs/history/superseded-work-rules.md`에 비활성 이력으로 보존한다.

- 등록 ID: `voca-nexus`, 이 대화에 연결된 heartbeat. 매시간, ACTIVE.
- 같은 로컬 main 디렉터리에서 누적 수정한다. 새 자동화/작업/복사본을 만들지 않는다.
- 앱과 컴퓨터가 켜져 있어야 한다. 절전·앱 종료·네트워크/사용량 제한 중의 실행 및 자동 복구는 실제 관찰 전까지 미검증이다. 추가 구매·API 전환 금지.
- 최초 등록과 아래 반복 작업은 분리한다. 매회 등록 명령을 재실행하지 않는다.

## 실행마다

1. `AGENTS.md`, `docs/AI_WORK_RULES.md`, `docs/WORKING_CONTEXT.md`, git status/diff를 대조한다. 이미 검증한 결과는 코드가 바뀌지 않았다면 재사용한다.
2. 수정 전에 저장소에서 `python scripts/hold-development-lock.py`를 대화형 터미널 세션으로 실행한다. `LOCK_ACQUIRED` 확인 후에만 수정한다. 세션 ID/PID를 기록한다. `LOCK_BUSY`이면 이번 회차는 수정하지 않는다. PowerShell 실행 정책은 바꾸지 않는다.
3. 이 잠금은 OS 파일 핸들로 유지된다. 보조 프로세스를 살아 있게 둔 동안만 유효하다. 작업 마지막에 그 터미널에 Enter를 보내 `LOCK_RELEASED`를 확인한다. 파일 자체는 비어 있어도 남으며 삭제할 필요 없다.
4. 갑작스러운 중단 후 잠금이 남으면 소유 터미널/프로세스와 원래 대화가 실행 중인지 확인한다. 실행 중이면 건드리지 않는다. 중단된 실행의 이 스크립트 프로세스임이 정확히 확인된 경우에만 해당 PID를 종료하여 해제한다. PID/소유 상태가 불확실하면 그 회차를 건너뛴다. 이 잠금은 규칙을 따르지 않는 외부 편집기를 막지는 않는다.
5. 우선순위: 데이터 보존·정답 오류 → 장애·회귀 → 흐름·저장 → 미완료 필수 기능 → 근거 있는 사용성 개선. 명시 요구와 추론 개선을 구분한다.
6. 작은 수정 단위로 파일·테스트 결과·다음 행동을 WORKING_CONTEXT에 저장한다. 한 회차 작업을 무한히 늘리지 않는다. 변경된 부분에 맞춰 검증하고 끝난 전수 검사를 이유 없이 반복하지 않는다.
7. 승인된 Pages 배포는 인증 확인 → 새 빌드 → 경로 감사 → 목적 파일만 커밋/push → Pages → 원격/공개 URL 확인 순이다. 실제 모바일 Safari/Chrome 미확인을 데스크톱으로 대체하지 않는다.
8. 사용량 오류의 복구 시각이 있으면 문서에 적고 그 이전 개발 재시도를 보류한다. 모르면 다음 예약에서 확인한다. 예약은 삭제하지 않는다. 스케줄러의 사용량 소진 후 재개는 아직 실측되지 않았다.
9. 변동 없는 상태는 반복 알림하지 않고 의미 있는 개선·중요 장애·필수 결정만 보고한다.
